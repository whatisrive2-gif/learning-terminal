# 复习、多来源与作业工作流

本参考用于首轮课程复习、课件与录音混合、手写笔记审计和作业辅导。它规定学习产物的结构与互动边界；命令和数据格式仍以 commands.md 为准。

## 先判定任务模式

- 首轮复习：目标是建立当日课程的完整知识结构，同时处理笔记卡点和作业。
- 局部重构：用户已经有主线，只需把某一段讲慢、补推导、换例子或纠错。
- 作业推进：以用户实际动笔为主，AI 用分层提示帮助完成并提升。
- 知识库整理：先保证内容正确和来源清楚，再规划写入位置与关联。

同一请求可包含多个模式。首轮复习的完整讲解不能因同时有问号或作业而被省略。

## 为不同来源分配职责

不要把所有来源拼成一段无差别摘要。先为每个来源确定角色，再交叉校验。

### 课件、教材、讲义

作为知识主线和符号基准。提取：

- 本节要解决的问题及章节结构；
- 定义、定律、公式、图示关系；
- 推导链条及每一步使用的条件；
- 典型例题、反例、边界和近似。

课件过于简略时，可补足连接性解释，但要区分材料主张与 AI 补充。课件自身也可能有笔误，不能仅凭版式权威跳过核对。

### 课堂录音、字幕、转录

用于恢复教师强调、口头例子、常见误区、考试提示和课件省略的过渡。重复口头语可以压缩。

转录不清或与课件冲突时：

1. 公式、符号和数值优先回到课件、教材或清晰板书核对；
2. 仍无法判定就标明不确定，不把听写猜测写成事实；
3. 纯录音无法提供缺失的图形、空间方向和板书细节。

### 手写笔记

笔记既是信息来源，也是用户当前理解模型的证据。必须检查全部相关内容，不只提取问号。逐条识别：

- 明确错误：与定义、定律或推导矛盾；
- 可能问题：字迹、上下文或符号不足，存在误读风险；
- 正确但缺条件：结论成立，但适用范围、方向、近似或初始条件遗漏；
- 推导缺口：用户请求推导，或中间跳步可能掩盖理解断点；
- 模型或方法选择问题：公式可能没错，但研究对象、对称性、路径、坐标系或守恒量选错；
- 正确且完整：予以确认，不制造不存在的问题；
- 无法辨认：明确指出需要更清晰图像或用户补充的局部。

建议输出“原笔记内容—判断—理由/证据—修正或下一步”，并在必要时给置信度。用户写下的问号只是审计入口之一。

### 作业、习题、测验

作业同时有两个目标：

1. 完成轨：保证任务最终可提交或可核对；
2. 提升轨：让用户经历建模、选路、列式、检查和迁移。

不要把作业答案直接混入课程讲解，也不要为了“引导”无限拖延完成。记录题目状态时区分未开始、已提示、用户尝试、需纠错、已完成和已迁移。

## 首轮复习的完整性门槛

一份首轮复习至少要让用户获得以下内容：

1. 今日课程在解决什么问题，以及它与前后知识的关系；
2. 核心对象、物理量或概念的含义；
3. 关键公式或规则，以及符号、方向和单位；
4. 主要推理或推导链，特别是容易跳步的地方；
5. 至少一个能体现方法选择的代表性例子；
6. 适用条件、失效边界和常见混淆；
7. 与手写笔记相连的审计结果；
8. 作业如何开始，但默认不提前泄露最终答案；
9. 本轮仍未覆盖或无法确认的内容。

不能把“回答了所有问号”称为完成首轮复习。若材料太长，应明确当前覆盖范围并保存阶段版本，继续补齐后再标记完整。

## 作业的渐进提示

### 提示阶梯

按需要逐级增加信息量，不要求机械走完每一级。

1. 题意层：要求什么、已知什么、容易漏掉什么条件。
2. 选路层：提示应使用的概念、定律、对称性或表示方法，并说明为什么。
3. 建式层：给出关键中间量、方程骨架或第一步，不代替用户完成全部代数。
4. 纠错层：针对用户实际尝试指出首个关键错误，保留其余可继续部分。
5. 完成层：给出完整、可核对的解法，包括条件、步骤、结果和检查。
6. 提升层：给一个低成本变式、反例或口头追问，检验方法能否迁移。

### 默认提示边界

默认只提供足以让用户迈出下一步的信息：

- 可以指出对象、守恒量、积分路径、坐标系、正负方向或方程类型；
- 可以给局部公式和检查方法；
- 不提前给最终数值、关键系数、完整坐标或闭式答案；
- 不用伪装成问题的方式暗示全部解法。

在以下情况提高提示等级：

- 用户展示了有效尝试，需要定位错误或核对结果；
- 用户明确要求更多提示或完整解答；
- 连续两轮仍卡在同一处；
- 缺失的先修知识使继续尝试没有训练价值。

在以下情况进入完成层：

- 用户明确要求答案或逐步解答；
- 用户已完成一轮真实尝试，答案用于核对与纠错；
- 有提交期限或“必须完成”的现实约束；
- 继续拆提示只会机械延迟，不再增加学习价值。

完整解答后不要停在抄答案：让用户做一次极短的复述、关键步骤填空、条件变化判断或同型变式。若用户只想赶进度，可把迁移练习留作建议而不强迫。

## 状态与证据分开

这些状态不能互相替代：

- 已覆盖：材料相应范围已经读取；
- 已讲解：已经形成可独立理解的解释；
- 已完成：作业已经得到完整可核对结果；
- 自述理解：用户表示“懂了”；
- 独立作答证据：用户在没有答案泄露的情况下实际完成关键步骤；
- 迁移证据：用户能处理条件变化或同型新题。

记录证据时保留用户的具体回答或关键步骤，不制造百分制掌握评分，也不因笔记保存成功推断长期掌握。

## 把实践经验升级为可复用规则

每次用户评价流程时，先确定最小正确作用域：

- 只针对本次材料或当前学习进度：保存到 session、need 或 revision；
- 针对某门课、某个项目或该用户的稳定偏好：写入项目级规则；
- 已多次验证、跨学科成立且用户希望以后复用：更新 learning-terminal skill；
- 涉及命令、数据结构或 UI 行为：再评估是否需要修改脚本、测试和参考文档。

升级 skill 前检查新规则是否会误伤其他学习场景。更新后至少用以下情形做前向检查：

1. 只有课件的普通首轮复习；
2. 课件、录音、手写笔记和作业混合；
3. 用户只要求局部解释；
4. 用户明确要求完整作业答案；
5. 用户禁用 Markdown 或阅读前端。

## 每轮结束的复盘

若用户要求持续优化工作流，输出末尾简要说明：

- 本轮实际采用了怎样的流程；
- 哪一步有效、哪里仍有摩擦；
- 哪些改进只是建议，哪些已经写入 session、项目规则或 skill；
- 学习终端输出结构和小功能下一步值得验证什么。

不要把尚未验证的界面设想写成已经实现的能力。
